# 节点独立验收文档设计

状态：用户批准并选择直接实施，现已完成。新增独立验收文档、显式旧关联转换、归档和草稿保护；实际项目未自动转换。验证与独立审查记录见 docs/acceptance-documents-ledger.md。

## 1. 用户意图与范围

用户明确要求：验收文档属于具体任务节点，而且独立于其他文档。之前实现的“验收项可引用任意普通文档”不符合这个边界，本设计取代该关联规则。

已确认的行为：

- 项目文档与普通节点文档仍按需创建，原有内容保留。
- 每个节点有独立的验收文档区域与真实文件夹。
- 每条验收标准可以关联零份或一份本节点验收文档。
- 验收项旁支持新建、选择、打开、更换和解除关联。
- 验收文档不参与普通“关联文档”的多选列表，也不混入普通节点文件夹。
- 旧普通文档不搬动、不删除；旧验收关联通过明确的复制操作转换，保留原件。

补充的安全设计，随本文一并审阅：删除节点时，其验收文档单独归档，不变成普通项目文档，不级联删除正文。

不开发外部文件自动同步、附件上传、签名审批、多用户权限、自动判定验收通过或任意文件移动。

## 2. 方案与组件边界

采用独立验收文档集合、专用命令和独立目录，复用已有 Markdown 编辑器、项目版本号与原子提交机制。

只在普通文档上标注 verification 并过滤列表，仍允许两种文档混用，不能清晰表达独立性，因此不采用。建立第二套存储服务和版本号则会增加跨库一致性问题，也不采用。

三个职责边界：

1. 普通文档模块：维护项目资料、开发路线、技术实现、普通验证记录等，保持现有功能。
2. 验收文档模块：维护节点专属验收正文、不可变归属与验收项引用。
3. 项目存储模块：在同一快照中提交两个集合，并生成各自 Markdown 文件；不存在第二份权威数据源。

普通文档中的 verification 类型仍可用于一般验证笔记，不会仅因类型名称而自动转成验收文档。

## 3. 数据与约束

项目新增可选数组 `acceptanceDocuments`，旧项目缺失时等价于空数组。

验收文档结构：

```json
{
  "id": "acceptance-unique-id",
  "taskId": "task-core",
  "title": "关键流程验收记录",
  "content": "# 验收记录\n",
  "archived": false,
  "updatedAt": "ISO 时间"
}
```

活跃验收文档必须归属于当前存在的一个节点；不允许项目级归属、跨节点移动，或通过普通文档保存命令修改。归属在新建后不可变。

验收项新增 `acceptanceDocumentId`：缺失、null 或空字符串表示不关联；非空值必须指向本节点的一份未归档验收文档。普通节点 `documentIds` 只能引用普通文档。两个集合使用不重叠 ID，避免编辑器、导出或路径查询发生歧义。

同一节点的多个验收项可以共用一份验收文档；不同节点不能共用。解除引用或删除验收项不会删除正文。

普通文档和验收文档合计最多 1000 份，包括归档验收文档。单份正文 500000 字符、标题 160 字符、完整 JSON 7 MB、请求 8 MB 的限制保持不变。每条验收项的正文引用不计入普通节点关联文档数量。

验收文档存在不等于验收通过。现有完成门槛不变：前置完成、至少一项验收标准、每项通过且有非空证据文字。

## 4. 界面与使用流程

### 节点详情

普通“关联文档”继续使用默认收起的滚动勾选列表，只包含普通文档。

普通“节点文档”区域保持原入口；另设紧凑的“验收文档”区域，显示本节点验收文档数量、查看文件夹和新建入口。不自动生成空文档，不在左侧导航平铺所有节点文件。

每条验收标准的选择器只列本节点未归档验收文档。无文档时显示“不关联”，同时提供“新建验收文档”。关联后可打开正文，更换或解除引用；相关修改仍通过“保存阶段”提交。

从验收项新建时，标题可自由填写，默认给出与该验收标准相关的标题。模板是可选的，包含验收目标、步骤、预期结果、实际结果、证据与结论；可从空白开始。

从验收项直接新建并关联，需要验收项已保存且仍然存在。节点有未保存修改时先明确询问是否保存；取消则保持原草稿，不创建文档。保存被校验或冲突拒绝时停止后续创建。

### 编辑与导航

验收文档编辑页明确显示“节点名 / 验收文档”，复用 Markdown 编辑、预览、分栏、保存快捷键和本地路径功能。普通文件夹与验收文件夹有明确的模式区分，切换后只显示对应集合。

左侧“项目文档”始终先进入普通项目文档，不能意外打开验收编辑器。顶部普通文档数量维持原含义，验收数量单独展示。

从验收项打开正文后，返回任务图会重新选择原节点。切换文档、文件夹、模式或项目前遵循现有草稿保护；相同文档重复选择、主题和预览模式切换不会丢失编辑。

## 5. 真实存储与查询

当前版本结构：

```text
revisions/<generation>/
├── snapshot.json
├── documents/<ordinaryProjectDocId>.md
├── tasks/<taskId>/documents/<ordinaryNodeDocId>.md
├── tasks/<taskId>/acceptance/<acceptanceDocId>.md
└── archived-tasks/<deletedTaskId>/acceptance/<acceptanceDocId>.md
```

文件路径使用稳定 ID，不使用标题。每次提交给当前节点创建验收目录，但不创建占位文档。已归档内容进入独立归档路径，不混入普通文档目录。

所有文档文件与 snapshot.json 写完后才切换 HEAD；失败保持原版本有效。历史版本和原件不重写、不清理。

storage API 保留原有普通路径字段，新增验收目录和验收文档路径列表。路径与版本号来自同一次 HEAD 读取；旧版本未生成的验收目录返回 exists=false，只读查询不会创建文件。

本地 Markdown 文件仍用于查看与备份；修改通过网页或代理 API 提交，外部直接改文件不会自动同步。

## 6. 命令、并发与删除

沿用 `POST /api/projects/<id>/commands` 和 revision 校验，不新增第二套写入协议。

- `saveAcceptanceDocument`：新建或保存正文，更新时保留归属，禁止归属或归档状态的任意修改。可选 criterionId 只用于新建时原子关联一个已存在的本节点验收项；校验失败不留下孤立文件。
- `deleteAcceptanceDocument`：确认后删除指定验收文档，并清空本节点所有对应验收引用；保留标准、结果、证据和旧快照。
- `convertAcceptanceDocument`：按 taskId、criterionId、原普通 documentId 和可选标题，原子复制正文并替换该项的旧引用，详见下一节。
- `updateTask`：继续修改验收数组，新增引用必须满足本节点归属约束。

其他窗口删除验收文档时，编辑中的节点草稿和基线只清理失效引用，不丢本地标准或证据，不把隐藏的旧 ID 提交回服务。共享字段冲突仍需明确确认，不盲目覆盖远端修改。

验收正文被远端删除时，草稿仍保留；恢复需明确确认并创建新 ID。原节点已删除时，不允许暗中恢复为普通文档或归属其他节点，保留可复制的草稿并提供取消操作。

删除节点：普通节点文档按现有规则转为普通项目文档；验收文档标记 archived=true，并记录删除时节点名供归档展示，保留原 taskId。归档文档只能阅读、复制内容或明确删除，不能关联到其他节点。编辑器提供“已删除节点的验收归档”入口，避免正文保留却不可发现。新建节点即使标题相同，也不会继承旧验收记录。

## 7. 旧数据兼容与转换

读取旧快照、刷新、查询路径和启动服务均不改写项目，不自动复制文档，不提升 revision。

旧验收项的普通 `documentId` 暂时作为兼容字段保留，界面明确标记“旧普通文档关联 · 待转换”，并提供原文查看、复制为本节点验收文档、解除关联。不将旧文档伪装成本节点验收文档。

新界面不再建立普通验收引用。用户明确执行转换时：

1. 校验 revision、原验收项和原普通文档仍然存在，旧引用与请求一致。
2. 在本节点创建独立验收文档，复制当时已提交的标题与完整正文，不移动原件。
3. 将该项改为 acceptanceDocumentId，清空旧 documentId。
4. 在同一次原子提交中保存；若容量、节点归属或磁盘写入校验失败，保留原有引用和内容。

转换后的正文独立维护；后续修改原普通文档不会同步修改验收副本。多个验收项需要共用副本时，可在转换第一项后为其他项选择该副本，不自动批量复制。

仅允许原有旧 documentId 引用在普通节点修改中原样保留或清空；不接受新增或更换这种旧式引用。验收项不能同时有非空旧 documentId 和新 acceptanceDocumentId。旧 API 客户端需要更新后才能建立新验收引用。

删除原普通文档只清理剩余旧引用，不影响已经转换的验收副本。JSON 导入支持旧快照及新集合，新版本导出包含独立验收文档与归档；旧版本应用不保证能打开新格式备份，文档应明确这个兼容边界。

## 8. 验证与交付标准

- 领域测试：同节点引用可用，普通文档、其他节点文档、归档文档、缺失或非法 ID 被拒绝；解除引用不丢正文；完成门槛不变。
- 文件与接口测试：两个集合各自路径、空目录、归档路径、真实正文、重启与 JSON 导入导出、单 HEAD 一致性、失败不切换版本、转换的原子性与原件保留。
- 浏览器测试：列表隔离、验收项新建/选择/打开/更换/解除、返回节点、旧引用提示和显式转换、取消不丢草稿、多个验收项独立、远端删除、冲突、深浅主题、手机滚动与键盘访问。
- 边界测试：复制后改原件或副本互不影响；超限转换失败不留副本；删除节点归档可访问，不伪装为普通项目文档。
- 完整运行现有测试，使用独立临时项目，不在用户真实项目上试写或自动转换。
- 更新 README、AGENT_GUIDE 与进度记录；交付时说明使用入口、旧关联转换方式和验证结果。
