# 节点专属文档文件夹设计

状态：用户于 2026-09-30 回复“符合”确认设计，回复“执行”批准实施；现已实现并通过 27 项领域/API 测试与 22 项浏览器测试。实际项目内容未改动。

## 1. 目标与已确认方向

用户希望每个阶段节点拥有自己的真实文件夹，记录工作路线、技术实现细节、验证和交接，供用户直观阅读，也供代理执行复杂长程任务时维护。

已确认采用真实文件夹和 Markdown 文件，不只是网页上的虚拟分组。现有项目级 Plan、Roadmap、讨论记录保留；节点状态、验收项与证据仍在任务详情维护。文档补充细节，不重复填报状态。

本设计另有两项明确边界，需随本文一起审阅：第一版不提供外部文件编辑的自动双向同步；删除节点时保留其文档，不级联删除。

## 2. 方案选择

- 推荐：扩展现有文档模型与版本目录。文档增加所属节点，写入该节点真实目录，复用现有编辑器、接口、版本冲突和原子提交机制。
- 仅做网页虚拟文件夹：实现更轻，但不满足真实节点目录的需求，因此不采用。
- 将可任意编辑的文件夹作为唯一数据源：有利于外部编辑，但需要监控文件、协调并发修改和处理删除冲突；第一版不采用。

第一版范围为一个项目内的“项目文档 + 节点文档”两级结构，不开发通用文件管理器、任意嵌套子目录、附件上传或同步服务。

## 3. 用户操作

### 节点入口

任务详情增加“节点文档”区域，显示专属文档数量、文件列表、“新建文档”和“查看文件夹”。空节点只显示简洁的创建入口，不自动生成四份空文档。

从节点进入文档页后，上方显示项目名与节点名，文档列表只显示该节点的文件。提供返回任务图的入口，返回时选中原节点并打开详情。若原节点已删除，回到任务图并给出一次提示。

创建文档可填写名称，选择工作路线、技术实现、验证记录、决策与交接等用途。可自由命名；用途不要求每个节点都创建一份。模板内容仅在用户选择并确认创建时生成。

### 项目文档入口

左侧“项目文档”默认展示原有全局文档。列表增加简洁的目录切换入口，支持选择“项目文档”或某个节点文件夹，不将全部节点文件平铺进侧栏。

节点的“关联文档”区域与“节点文档”区域分开：前者引用全局 Plan、Roadmap 等，后者展示专属内容。引用不改变归属，也不复制文件。已有 `documentIds` 引用继续有效；用户能打开已关联文档。

顶部文档数量统计整个项目内的文档总数。节点区域统计该节点拥有的文档数量，不计全局引用。

### 文件夹查看

展示并允许复制当前已提交版本中的本地绝对目录路径。浏览器不承诺直接打开操作系统文件管理器，也不提供任意路径访问接口。

文件夹是版本化目录：保存项目后，当前版本路径会变化；界面读取并展示最新路径。版本文件用于查看和备份。修改通过面板或代理接口保存；直接修改版本内的 Markdown 文件不会同步回应用，界面在路径详情里说明此边界，不常驻冗余提示。

## 4. 文档模型与兼容性

保持 `project.documents` 为完整文档数组，不新增独立副本。

文档增加可选 `taskId` 字段：缺失或 `null` 表示项目文档，合法任务 ID 表示该节点所有。校验拒绝不存在的所属任务和非法 ID。旧快照、旧 JSON 导入和现有三个文档均保持项目级归属，不自动分配到节点。

文档类型保留 `plan`、`roadmap`、`notes`，新增 `technical`、`verification`。界面以中文用途显示，名称与用途相互独立。

`saveDocument` 在新建时接受 `taskId`；更新已有文档时，未传 `taskId` 必须保留原归属，不能因旧客户端缺字段而变成项目文档。普通内容保存不允许修改归属，防止陈旧客户端意外搬动文件。第一版不提供任意移动文档的界面或命令；归属变化仅允许下述删除节点保留策略。

文档总数上限从 100 提升至 1000，以支持多节点文档。单文档内容上限 500000 字符、项目完整备份 7 MB、HTTP 请求 8 MB 保持不变。节点引用数量上限仍为 100；专属文档不需要重复加入 `documentIds`。

## 5. 真实目录与提交一致性

沿用现有 `HEAD` 指向当前已提交版本的机制，不新增第二套权威数据源。

```text
data/projects/<projectId>/
├── HEAD
└── revisions/<generation>/
    ├── snapshot.json
    ├── documents/<docId>.md
    └── tasks/<taskId>/documents/<docId>.md
```

`documents/` 保存全局文档，`tasks/<taskId>/documents/` 保存节点文档。每次提交为每个节点建立其目录，即使暂时没有文档，也不创建占位文件。

路径使用经过校验的不可变 ID，不使用节点或文档标题：重名、中文标点、斜杠和重命名不会造成覆盖或目录穿越。界面展示人类可读的标题，复制文件路径时使用实际 ID 文件名。

所有 Markdown 文件与快照写入完成后才切换 `HEAD`。失败保持原版本有效；旧版本不重写、不清理。旧版本全局 Markdown 的现有路径无需迁移。新格式仅在后续成功提交时生成。

新增只读 `GET /api/projects/<projectId>/storage`，返回读取到的 `HEAD` 对应版本号、项目文档目录、各节点文档目录与文档文件路径。只能查询指定项目的当前版本，不接受任意磁盘路径。响应不混入 JSON 导出快照，导入后的路径根据新项目 ID 重新计算。

## 6. 保存、删除与并发

所有修改继续使用项目 `revision` 和现有命令接口。节点文档同样支持手动保存、Ctrl/⌘+S、草稿保护、重复选择不丢编辑、409 冲突提示和代理更新后的字段对照。

切换项目、文件夹或文档前检查未保存修改。主题切换与分栏模式切换不改变草稿。轮询时保留当前文档上下文；其他窗口新增文件时刷新列表，不重置正在编辑的内容。

删除文档需确认，解除所有节点对它的引用；旧版本仍可恢复。

删除拥有文档的节点时，确认信息明确告知“其文档会保留到项目文档”。同一次命令把所属文档 `taskId` 置为 `null`，删除任务及其连接，保留文档 ID、内容和其他节点引用。新版本不再有被删节点目录，历史版本保留原目录。

若所属节点被其他窗口删除，文档跟随最新快照成为全局文档；保留用户未保存的内容草稿，不提交已失效的旧归属。若文档本身被其他窗口删除，恢复草稿必须明确确认并按当前可用归属新建，不静默覆盖。

## 7. 代理使用与范围

代理开始节点工作时，读取全局 Plan/Roadmap、节点专属文档及其引用，再按实际需要更新路线、技术细节、验证或交接内容。

代理通过 `saveDocument` 和 `revision` 保存，由存储层生成真实文件；不直接编辑 `HEAD`、快照或历史 Markdown。验收结果仍以节点标准和可验证证据为准，不因某份文档存在就标记完成。

第一版不自动执行文档命令，不将本功能扩展为收费视频教程网站的实现，也不自动给现有节点写未经讨论的技术方案。

## 8. 验收与验证

1. 两个不同节点分别创建文档，目录与内容互相隔离，全局文档不会混入。
2. 从节点打开、创建、编辑、保存、返回任务图与重启恢复均正常；真实 Markdown 内容与已提交快照一致。
3. 旧项目和旧导出 JSON 可直接读取、导入；旧客户端保存节点文档不丢归属。
4. 重名或重命名节点与文档不覆盖文件；非法 ID、所属任务缺失和目录穿越请求被拒绝。
5. 删除节点将其文档转为项目文档，内容、引用和历史版本保留；删除文档仅影响指定文件与引用。
6. 并发写入只有一个版本成功；保存失败不切换有效版本。冲突、跨窗口删除、文件夹切换和重复选择不静默丢草稿。
7. 导出再导入保留归属，导入项目的本地路径独立生成；超限输入不改变原快照。
8. 深浅主题、桌面和手机都可用，无横向页面溢出；文档编辑仍安全转义 Markdown。
9. 运行现有 16 个领域/API 测试及 12 个浏览器回归，增加模型归属、生成 DAG 与文档组合、存储路径和浏览器节点文档测试；测试用临时数据，不修改用户实际项目。
